# XScope

XScope 是一个本地优先的 X/Twitter 浏览器工具箱。当前版本提供“用户热度”和“搜索补漏”：打开一个 X 用户主页后，在页面右侧显示一个侧栏，优先复用 X 网页已经发出的 GraphQL 时间线请求，通过游标分页获取公开推文，并按点赞、回复、转发或浏览量查看热门内容。

## 当前版本：v0.2.0

## 当前功能

- 自动识别 `x.com/<用户名>` 和 `twitter.com/<用户名>` 用户页面
- 在网页右侧显示可收起侧栏
- 如果安装扩展前已经打开 X 页面，点击工具栏图标会自动补注入页面脚本
- 优先通过 X 网页内部 GraphQL 时间线分页收集推文，不需要移动页面
- 对已经加载的 `UserTweets` / `SearchTimeline` 响应进行本地捕获和去重
- 搜索框支持本地搜索；“X 搜索”会自动组合 `from:<当前用户名>` 并打开最新结果
- 在 X 搜索页点击“抓取搜索结果”，可以继续通过游标分页补充本地数据
- GraphQL 失效时保留自动滚动扫描作为兜底
- 本地缓存，不使用官方 X API、不上传推文、不读取 Cookie
- 按点赞、回复、转发、浏览量排序
- 默认只展示原创推文，也可以切换查看回复和转发
- 展示收集数量、最早日期、上次更新时间和当前数据来源
- 点击结果直接打开原推文

## 重要限制

这是一个免费、尽可能本地化的工具，不是官方全量历史数据接口。GraphQL 分页可以减少对 DOM 滚动和页面懒加载的依赖，但 X 的内部接口没有稳定的公开契约，queryId、请求字段和返回结构都可能变化。删除、私密、暂停或对当前账号不可见的推文也无法读取，因此侧栏会明确提示扫描范围，不承诺“账号全部历史”。

当前每个账号最多缓存 5,000 条推文。获取历史或搜索分页过程中可以点击“停止”，已经收集的内容仍会保存在本地。

## 推荐使用方式

1. 打开用户主页，先点击“获取历史数据”。这会使用 X 当前页面捕获到的 `UserTweets` 请求进行分页。
2. 如果想找特定内容，在搜索框输入 `115`、`直充` 等词，先点“本地”搜索已经保存的数据。
3. 本地没有结果时，点击“X 搜索”。插件会打开类似 `from:用户名 115` 的 X 搜索页；在新页点击“抓取搜索结果”补充数据。
4. 如果页面没有捕获到 X 的内部请求，刷新 X 页面后重试；仍然失败时可以使用“滚动兜底”。

## 本地安装

1. 下载或克隆本仓库。
2. 打开 Chrome、Edge、Brave 或其他 Chromium 浏览器的 `chrome://extensions`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择本仓库目录。
5. 打开一个 X 用户主页，点击右侧 X 圆形按钮，再点击“获取历史数据”。

如果点击工具栏图标没有立刻看到侧栏，先刷新 X 页面，再点击一次扩展图标；最新版也会尝试自动补注入脚本。GraphQL 网络桥接需要在 X 页面加载早期安装，更新扩展后建议刷新已经打开的 X 标签页。

更新代码后，在扩展管理页点击 XScope 的刷新按钮即可重新加载。

## 隐私与安全

XScope 只申请 `storage` 和 `scripting` 权限，并只在 X/Twitter 页面运行。推文数据存储在浏览器本地。网络桥接只在页面内存中暂存 X 已经发出的必要请求信息，不把认证信息发送到外部服务器，也不会把认证信息写入缓存。项目不包含点赞、关注、评论等自动化操作。

X 的页面结构可能随时变化。如果扫描结果异常，请提交页面结构和浏览器版本信息，不要提交 Cookie、令牌或账号密码。
